TikTok in Palmyr is direct browser automation — no paid upstream API. You pay per action in USDC over x402; the wallet that signs the payment owns the session. Account management is free local-vault; the action ops run server-side through the account's residential IP.

<Note>

<Note>
  No TikTok password is ever stored server-side. A session is captured from a real-browser login, and the default `connect` flow is a QR hand-off — the password never leaves the phone.
</Note>

## Connect an account

`connect` is a QR hand-off — zero install, nothing to type, never blocked by TikTok.

<Note>
  **Prefer `--server`.** The login happens inside the account's own persistent browser profile on the server, which is the same browser that later posts. Nothing is transferred afterwards, so no device or IP mismatch is baked in at login, and later ops need no cookies at all. The login browser starts when the person opens the link and exits from **their** country — TikTok rejects a scan whose phone and browser are in different countries, since that is the shape of a QR phishing attack.

  ```bash
  palmyr tiktok connect <username> --server
  ```
</Note>

<Steps>
  <Step title="Run connect (QR default)">
    ```bash
    palmyr tiktok connect <username>
    ```
    It prints a `/connect/<token>` link (in stderr and as `qr_link` in the result).
  </Step>
  <Step title="Scan from the phone">
    Open the link and scan the QR with the **TikTok app on the phone** where the account is already logged in. No password, no captcha.
  </Step>
  <Step title="Session captured">
    The link is durable (~15 min) and auto-refreshes as TikTok rotates the code (the page polls `/connect/<token>/status`). The session is captured the moment they confirm.
  </Step>
</Steps>

To log in on the current machine instead, use `--local` — it opens Chrome/Edge/Brave here and captures the session via CDP with no server call:

```bash
palmyr tiktok connect <username> --local
```

Already have cookies from a logged-in browser? Import them directly:

```bash
palmyr tiktok import <username> --sessionid <s> --csrf <c> --webid <w> --country <iso2>
```

## Post a video

```bash
palmyr tiktok post <username> --file video.mp4 --caption "ship day"
```

Use `--url <https>` instead of `--file` to post from a URL. `--privacy` takes 0/1/2 = public / friends / private (default public).

## Safety

- **No server-side password.** The session is captured from a real-browser login; TikTok credentials never sit on Palmyr's servers.
- **Its own residential IP.** Each account is pinned to a single residential exit in its own country — a consumer ISP, not a datacenter — and reuses it for every action, so Palmyr's server IP never appears to TikTok. Two of your accounts in the same country get *different* exits, so they can't be linked to each other by IP.
- **Nothing to configure.** The country is taken from whoever scans the QR and stored on the account, so agents never pass it. (`--country` only overrides it when you deliberately want a different market's exit.)
- **Its own browser profile.** With `connect --server`, the browser that logs in is the one that later posts, and it keeps its cookies, cache and storage between actions — so the account returns as the same device rather than arriving from a brand-new machine every time.
- **Hook results are measured, not asserted.** Lift is always against the account's own median. Posts younger than 7 days are excluded (still distributing) and posts older than 90 days are excluded too, because **hooks decay** — an opening that printed views last year is not evidence about what works now. Every report states the window it covers, and any pattern with fewer than 3 mature posts is flagged as not confident. Nothing here is a claim about TikTok at large: it is your accounts, measured.
- **Drafts are a human approval gate.** Stage with `draft`; nothing publishes until you `approve`, and a failed approve keeps the draft for retry.
- **Audit logs.** `logs` records every post that actually went out — account, caption, timestamp, and source.
